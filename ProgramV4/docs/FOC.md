## 制御の流れ

```
TIM1 (20 kHz, センター揃えアップダウン, ARR=1800)
  │  上りで CNT = 1750 (頂点の50カウント手前) を通過 → OC4REF 立ち上がり → TRGO2
  │  低側FETのON区間は頂点を中心に広がるので、ここが区間の中央 = 平均電流が取れる
  ↓
ADC1 が U相/V相 の電流を1点サンプリング
  ↓ DMA転送完了割り込み  ← ここが制御ループのタイミング
HAL_ADC_ConvCpltCallback()   [bldc.c]
  ├─ BLDC_UpdateEncoder()    20 kHz : 角度追従オブザーバ (2次PLL) → 機械角と角速度
  ├─ BLDC_OuterLoop()         1 kHz : 速度/位置PID → Iq指令 [A]
  ├─ BLDC_DirectIqLoop()     20 kHz : トルク/制動/停止モードのIq指令 (指令の素通し)
  └─ BLDC_CurrentLoop()      20 kHz :
        電流取得 → 過電流判定 → 電気角 (+角度遅れ補償) の sin/cos
        → Clarke → Park → Id/Iq の PI → 逆起電力・dq干渉の FF
        → 電圧ベクトルの円制限 (+アンチワインドアップ)
        → 逆Park → SVPWM → CCR1/2/3 書き込み
```

モード (`BLDCMode`): STOP / SPEED / POSITION / TORQUE / BRAKE。

- SPEED: 指令を `MAX_ANGULAR_SPEED` でクランプし、`MAX_ANGULAR_ACCEL` でスルーレート制限してから PID。
- POSITION: 目標角との偏差 (`FOC_AngleDiff` で ±π) をそのまま PID に入れる素の構成。整定したら電流を0にする。
- TORQUE / BRAKE / STOP: PID を通らず指令を素通し。BRAKE は `-tanh(ω/BRAKE_BOUNDARY_SPEED_RAD_S)` で
  チャタリングを防ぎ、`BRAKE_DEADBAND_SPEED_RAD_S` 未満はトルク0 (係数は 1 kHz で更新)。
- 全モード共通で、最終的な Iq 指令を上位指定の `torque_limit` (= `svc.iq_limit`、上限 `MAX_CURRENT`) で飽和させる。
  詳細は [SERIAL_PROTOCOL.md](SERIAL_PROTOCOL.md)。

## 割り込み優先度

20 kHz の制御ループを最優先にしてジッタを抑えている (`CurrentSense_Init` 内で設定)。

| 割り込み | 優先度 |
|---|---|
| DMA1_Channel1 (ADC1 = 制御ループ) | 0 |
| SysTick | 1 |
| DMA1_Channel4-7 (UART) | 2 |
| DMA1_Channel2 (ADC2) | **無効化** (値は DMA が勝手に更新するので不要) |

## 実行時間

`-O2` ビルドで **CPU 使用率 約34%** (割り込み 平均 16.9 µs / 最大 19.9 µs、周期 50 µs。2c 後の実測)。
最新値は `PROFILE_ISR` で測れる (使い方は [OPTIMIZATION.md](OPTIMIZATION.md))。
制御周期は割り込みが `ISR_DEADLINE_US = 23.4 µs` を超えるとデューティの反映が1周期ずれるので、それが上限。

割り込みの中を触るときは次を壊さないこと。

- **倍精度演算を作らない**。`mymath.h` の `PI` / `TWO_PI` は `double` で、単精度FPUのみの Cortex-M4 ではソフト演算になる。
  割り込み内では `PI_F` / `TWO_PI_F` / `FOC_NormalizeRadians()` / `FOC_AngleDiff()` を使い、リテラルには `f` を付ける。
- **sin/cos は `FOC_SinCos()`** (CMSIS-DSP の 512点テーブル直引き。縮約を1回で済ませ sin と cos を同時に返す)。
  入力範囲は任意なので事前に正規化しない。`mymath.h` に三角関数を足さない。
- **PWM 出力は `TIM1->CCRx` 直書き** (`PwmOut_Write` は1相約100命令)。
- **平方根は `FOC_Sqrt()`** (VSQRT.F32 一命令)。
- **float の比較・`Abs()` / `Constrain()` を増やさない**。`VCMP`+`VMRS` は1回8〜10サイクルかかる。
  `Abs()` は float で `VABS.F32` になるよう振り分け済み、デューティのクランプは整数比較にしてある。
- エンコーダのラジアン変換係数は初期化時に事前計算する。

`arm-none-eabi-objdump -d build/ProgramV4.elf` で割り込み配下に `__aeabi_*` (倍精度) が無いことを確認できる。

## 変調とデューティ上限

SVPWM は min-max 方式 (三次高調波重畳)。最大値と最小値の中点を全相から引き、線間電圧を変えずに
相電圧のピークを下げて、母線電圧の利用率を正弦波変調の 2/√3 (約15%) 倍にする。

ローサイドシャントの都合で `MAX_DUTY = 0.88` (`MAX_DUTY_CCR = 1584`) に制限しており、
出せる相電圧振幅は `(0.88 - 0.5) × 2/√3 = 0.439 × Vdc` (理論上限は 0.577 × Vdc)。これが `MAX_MODULATION_RATIO`。
エッジ揃えの頃は 0.80 (変調率 0.346) だった。経緯は [OPTIMIZATION.md](OPTIMIZATION.md)。

さらに電圧を出したくなったら:

1. **アンプの整定時間を実測して `CURRENT_SENSE_SETTLING_COUNTS` を詰める**。現在の 144 カウント (2.0 µs) は
   データシートからの保守的な見積もり。ADC のトリガ位置をスイープすれば MCU だけで測れる
   (手順は [OPTIMIZATION.md](OPTIMIZATION.md))。0.92 程度まで見込める
2. ADC のサンプリング時間を 61.5 → 19.5 cycles に短縮する (基板の RC フィルタ次第)
3. デューティが高い相の電流を推定で補う (相電流再構成)

## 電気角

`elec_theta = (mech_theta + ω̂ × angle_delay) × POLE_PAIRS`

- 観測角は `θ_meas = θ_lin − encoder_offset_theta − lut(θ_lin)`。θ_lin は ADC 値の線形写像 (向き `encoder_dir` 込み)、
  lut は校正で作る補正テーブル (磁石の偏心・INL)。校正後は `mech_theta × POLE_PAIRS` が d軸 (ロータ磁束方向) に一致する。
  静的なずれは校正 5 (ψm・遅れの掃引) が δ0 として測ってオフセットに足し込むので、手動のオフセット定数は持たない。
- **角度遅れ補償**: AS5600 の内部フィルタ (約1 ms) と演算遅れ (0.075 ms) のため推定角は実位置より遅れ、
  回転中は速度比例の角度ずれ δ = ω_e × 遅れ になる。ω̂ ぶん先に進めて打ち消す。
  補償しないと 120 rad/s で電気角が約49°ずれ、逆起電力が d軸に漏れて Vd が本来の約40倍になる (実測)。
  遅れ時間はスイッチ校正で自動測定する (校正 5)。

**確認方法**: `STATUS_PRINT_INTERVAL_S` を有効にして高速で回し、`Vd` がほぼ0なら合っている。
負に大きければ補償不足、正に振れたら進めすぎ。無負荷でトルク指令を入れたとき `Id` が 0 付近、`Iq` が指令に追従するのも目安。

## エンコーダ周りではまった点 (実機で解決済み)

機械角の誤差は**極対数倍 (7倍) されて電気角の誤差になる**ので、ここは特に慎重に扱うこと。

### 起動時に機械角を実測値で確定させる (`encoder_primed`)

`mech_theta` を 0 から実角度へ収束させると、その間に電気角が何回転もして電流制御が破綻する
(起動直後に相電流が 8 A 近くまで跳ね、トルクモードでは過電流保護が発動していた)。
`BLDC_UpdateEncoder` の初回は `mech_theta = theta_meas` とし、`BLDC_Init` でも制御ループを回す直前に一度呼ぶ。
校正中のオフセット測定でも、ロータが動いたあとに `encoder_primed = false` で張り直す必要がある
(HAL_Delay(1) で回る校正ループではオブザーバが追従できず、追従中のランプが平均に入って電気角で約70°ずれる)。

### 角度追従オブザーバ (2次PLL) — 速度の微分をやめた

**症状**: トルク制御は滑らかなのに、速度制御だと**機械1回転ごとに「がくっ」**となる。
犯人は速度制御だけが使う `angular_speed` の推定値で、周期は機械1回転 = エンコーダの 0/2π の継ぎ目。

**原因**: AS5600 のアナログ出力はレール付近で飽和し、継ぎ目の手前の数度は実際に回っても ADC 値が変わらない。
角度が凍結して測定速度が 0 に落ち、飽和を抜けた瞬間に溜まった差が一気に現れて、旧実装の微分が
800 rad/s 相当の速度を拾っていた (目標 10 rad/s でも Iq 指令が上限に張り付いた)。

**対策**: 微分をやめ、推定角 θ̂ を観測角に追従させるループを回して、その内部状態として θ̂ と ω̂ を同時に得る。

```
e   = θ_meas - θ̂                (イノベーション)
ω̂ += PLL_KI * e * dt            (速度推定 = 積分器)
θ̂ += (ω̂ + PLL_KP * e) * dt      (角度推定)
```

閉ループは標準2次系で `ω_n = √KI`, `ζ = KP/(2√KI)`。ζ=1 (臨界制動) として `KP = 2ω_n`, `KI = ω_n²`、
`PLL_OMEGA_N = 900 rad/s` (`config.h`)。調整は `PLL_OMEGA_N` だけでよい。

| | 微分 + ローパス (旧) | 2次PLL (現行) |
|---|---|---|
| 量子化ノイズ | 微分が高周波を持ち上げる | 積分器なので平滑 |
| 等速回転での遅れ | ローパスのぶん位相が遅れる | 定常誤差ゼロ |
| 観測の欠測 | そのまま速度スパイクになる | ω̂ で外挿して乗り切る |

観測値のゲートは2種類あり、**扱いを分けることが必須**:

- **飽和検出**: 生の ADC 値がレール付近 (判定幅 `encoder_margin` は校正で静止ノイズ σ から決める) なら角度情報が無いので棄却し、外挿する (最大 `ENCODER_REJECT_MAX` = 50 ms)。
- **グリッチ検出**: イノベーションが `ENCODER_INNOVATION_LIMIT_RAD` を超えたら `ENCODER_GLITCH_MAX` (1 ms) だけ棄却。続くなら推定が本当にずれているので棄却をやめ、全量を PLL に通して再ロックさせる。

速度推定 (積分パス) のイノベーションは**ロック中のみ** `PLL_SPEED_ERROR_LIMIT_RAD` で制限する
(継ぎ目の段差が全量 ω̂ に入って1回転ごとに Iq がスパイクするのを防ぐ)。再取得中に制限してはいけない
(次項)。比例パスは常に無制限なので、段差は角度補正として素早く吸収される。

**確認方法**: `STATUS_PRINT_INTERVAL_S` を有効にすると継ぎ目の状態が出る。

| 表示 | 意味 | 読み方 |
|---|---|---|
| `sat:` | 飽和で棄却したサンプル数 | 1回転あたり数十〜数百なら AS5600 が飽和している (正常な検出) |
| `glt:` | イノベーション過大で棄却した数 | 継ぎ目の遷移グリッチのぶん。`ENCODER_GLITCH_MAX` の倍数に近い値が1回転ごとに出る |
| `emax:` | 採用したイノベーションのピーク [rad] | **継ぎ目の段差そのもの**。0.01 程度なら校正良好、0.05 超ならエンコーダ校正の精度不足 |

`emax` が大きいときは観測器のゲインではなく**エンコーダ校正をやり直す**のが正しい対処。

### ロックが戻らなくなった話

**症状**: トルク制御で回しているロータを手で止めると、離しても復帰せず脱調したような動きのままになる (手で回すと直る)。

**原因**: オブザーバ導入時の棄却ロジックの設計ミス2つ。

1. 「観測できない」と「推定がずれている」を混ぜて棄却していた。急停止すると θ̂ が ω̂ のまま自走してイノベーションが大きくなるが、
   それを「異常な観測」と判定して棄却すると ω̂ が補正されず、自走が続く。**自分の誤差を理由に自分を補正しない**自己維持ループになっていた。
2. 積分パスのイノベーションに常時上限をかけていた。`dω̂/dt` が `PLL_KI × 上限` で頭打ちになり、手で止めたときの急減速に原理的に追従できなかった。

**教訓**: 推定器の外れ値棄却は、推定器自身がずれたときに自分のずれを外れ値と誤認しうる。棄却には必ず打ち切り条件を付け、
「観測が悪いのか推定が悪いのか」を判定できる材料 (今回は生の ADC 値) で分岐すること。
「ロック中は疑い、ロックを失っていたら信じる」。

**再ロックの速さ**: 引き込み範囲はおよそ `PLL_KP` で決まる。`PLL_KP ≥ MAX_ANGULAR_SPEED` を満たしていれば、
どの運転速度から急停止しても再ロックする。`PLL_OMEGA_N` を下げるときはこの条件を割らないこと。

### アナログ出力の盲点とスケール補正

AS5600 のアナログ出力はレール付近で飽和するため、1回転あたり角度が読めない区間 (盲点) がある。
実機では 1回転あたり 108 サンプル (5.4 ms) で、20 rad/s のとき 0.108 rad (6.2°、1周の1.7%)。

ADC 値 `[min, max]` がカバーするのは 2π ではなく **2π − 盲点幅**。`2π / (max - min)` をスケールにすると
θ_meas が1.7%引き伸ばされ、盲点を外挿で渡るたびに約 0.11 rad の段差が出る (速度に依存しない)。

**対策**: 校正時に盲点幅を測ってスケールから差し引く。

```c
svc.encoder_scale = (TWO_PI_F - svc.encoder_dead_zone) / range;   // BLDC_UpdateEncoderScale
```

盲点幅は校正 3 の正転・逆転の走査で、飽和していたサンプルの割合から求める
(強制角は ISR が等速で進めるので、時間の割合 = 機械角の割合)。校正側 (`bldc_calibration.c`) と運転側 (`bldc.c`) は
同じ判定 `BLDC_IsEncoderSaturated` を使うこと。

`ENCODER_INNOVATION_LIMIT_RAD` は実測 `emax` (約 0.09 rad) より十分大きくすること。近いと偶然の連続超過で
再取得モードに入り、積分パスの制限が外れて速度スパイクが復活する。現在の 0.25 rad で約2.7倍の余裕。

### 根本対策 (次の基板)

CurcuitV4 は AS5600 の SDA/SCL が未接続でアナログ出力しか使えない。I²C を繋げば 12bit のデジタル角度を直接読め、
飽和・ノイズ・遷移グリッチの問題がまとめて消える。なお **OUT ピンにコンデンサを足すのは逆効果**
(遷移が緩やかになって中間値を拾うサンプルが増え、位相遅れがそのまま電気角の誤差になる)。

## 校正とモータ定数

スイッチ (PA12) を押しながら起動すると `BLDC_Calibrate` が次を実行し、**全部成功したときだけ** `BLDC_Init` が `BLDC_SaveCalibration` で1回で Flash に保存する。
**既定値は持たない**: Flash に有効な校正値が無ければ `BLDC_IsCalibrated()` が偽で、app はトルク上限を 0 に固定する (駆動しない)。
校正電流 `CALIB_CURRENT_RATIO × MAX_CURRENT` (既定 3 A) を基準に、各測定の電圧・電流・速度は自動で決まる。

測定はすべて**制御ループの中で記録・平均する** (`BLDC_CalibIsr` 20 kHz / `BLDC_CalibOuterIsr` 1 kHz)。
メインループの `HAL_Delay(1)` は HAL の仕様で約 2 ms 待つので、周期の基準にしてはいけない
(旧 J 同定はこれで加速度を約1/2に読み、J と速度ゲインが約2倍になっていた)。
電流のゼロ点校正は割り込み開始前に済ませ、モータ定数の校正はすべて**電流制御と過電流保護が働く状態**で行う。

| # | 測定 | 方法 | 得るもの |
|---|---|---|---|
| 1 | R, L | 強制角0で Vd を直接印加 (PIバイパス)。Id が校正電流に届く電圧 V_cal を探し、0.25〜1.0×V_cal の4点の定常値を最小二乗。V_cal のステップを4回同期加算し、電流LPFを逆算してから ln(1−i/i_ss) の傾きで τ | R, V0 (デッドタイム), L = τR |
| 2 | 電流帯域 | 強制角0で Id ステップ。実測帯域が `CURRENT_BW_TARGET_HZ` になるよう設計帯域を補正し、もう一度測って確認 (オーバーシュート 15% 超は失敗) | `current_bw_hz` |
| 3 | エンコーダ | 電流制御の強制転流で正転2周・逆転1周 (1周2秒)。真の機械角 φ = 強制角/P を 128 ビンに分けて生値を平均 | レール (min/max)、ノイズ σ → レール判定幅、盲点幅、回転方向、オフセット、補正テーブル |
| 4 | J/Kt と摩擦 | トルクモードで +I 加速 → −I 減速 (正逆とも)。同じ速度帯の加速度差から J/Kt、和から摩擦。I は加速度と記録長から自動調整 | `j_per_kt`, `friction_current` → 速度ゲイン |
| 5 | ψm と角度遅れ | 速度制御で正逆 ±{¼,½,¾,1}×試験速度の8点。Vq から ψm と V0、Vd/Vq の比から各点の δ を出し δ = δ0 + ω_e·Δt を当てはめ | ψm、遅れ、静的な電気角のずれ δ0 |

**順序の理由**: 2, 3 は 1 の電流PIゲインが要る / 4 は電気角 (3) が要る / 5 は速度ゲイン (4) が要る。
速度ゲインに必要なのは J/Kt だけなので、ψm より先に決められる (旧手順は手動の速度ゲインで ψm を測っていた)。

**エンコーダ校正の要点**:
- 正転と逆転の平均を取るので、摩擦による引き込み遅れと AS5600 の遅れが相殺される (旧手順は正転側からの引き込みのみ)。
- レールは単発の極値ではなくビン平均の最小/最大から取る (ノイズの外れ値に引っ張られない)。
- 失敗判定: レンジ不足 / 回転方向が決まらない / 補正量の隣接差 > 0.1 rad (滑り・`POLE_PAIRS` の不一致) /
  正逆差 > 0.1 rad (ロータが強制角に付いてこない) / 有効ビン < 3/4。
- 補正テーブルは θ_lin の等間隔格子に写し替えて持つ (`CalibMath_BuildLut`)。ISR では線形補間するだけ。

**J/Kt の測り方**: (J/Kt)·a_acc = I − i_f(ω)、(J/Kt)·a_dec = −I − i_f(ω) なので、同じ速度帯で比べれば
速度に依存する摩擦も差で消える: `J/Kt = 2I / (a_acc − a_dec)`。加速度はオブザーバがロック中に追える上限
(`PLL_KI × PLL_SPEED_ERROR_LIMIT_RAD` ≒ 4050 rad/s²) の8割以下に抑える。超えると加速度を低く読み J を過大評価する。
**機構を付けたまま測れば、その反射慣性と摩擦込みの値になる。**

通常起動時は Flash から読み出し、マジック・チェックサム・範囲検査を全部通ったときだけ採用する。

**Flash フォーマット**: 項目を追加/変更したら `BLDC_FLASH_MAGIC` を必ず変えること (現行 "BLD5")。
Flash はページ消去を伴うので必ず1回で全項目を書く。校正ページ (0x0800F800〜) にコードが侵入しないよう、
リンカスクリプトの FLASH は 62K にしてある (以前は 64K で、侵入してもリンクが通っていた)。

**母線電圧**: `BLDC_Init` には実測の母線電圧を渡すこと。SVPWM の電圧→デューティ変換に使うので、暫定値で校正すると
指令電圧と実電圧の比がずれ、ψm だけが狂う (12 V 暫定・実測 8.6 V のとき ψm が 0.002663 対 真値 0.001908 だった)。

**参考 (旧手順での実測, 2026-07-29)**: R 0.1928 Ω、L 38 µH、ψm 0.001854 Wb、角度遅れ 1.08 ms。新しい校正の結果の比較に使う。

## ゲイン調整

### 電流PI

```
Kp = L × 2π × f_bw     [V/A]
Ki = R × 2π × f_bw     [V/(A·s)]       (f_bw = 校正 2 で決めた current_bw_hz)
```

L, R は校正値 (Flash) から `BLDC_UpdateCurrentGains()` が計算する。PI のゼロ点 Ki/Kp が R/L を打ち消すので、
閉ループは帯域 f_bw の1次系になる。**帯域の上限はプラントではなく位相遅れ**で、1.5周期の演算遅れと電流LPFを合わせて
700 Hz で位相余裕 約53° (`CURRENT_BW_TARGET_HZ` = 700 が狙い)。実測帯域は設計値より2〜3割低く出るので、
校正 2 が実測して設計帯域を補正する (以前は手動で `CURRENT_BW_HZ` = 850 に水増ししていた)。

### 速度/位置PID

出力は Iq 指令 [A]。位置PIDは `BLDC_InitOuterGains()` の手動値 (kp 15 / ki 30 / kd 0.05)。
速度PIDは校正 4 の J/Kt から `BLDC_UpdateSpeedGains()` が計算する (手動の既定値は廃止):

```
Kp = (J/Kt) × 2π × SPEED_BW_HZ           [A/(rad/s)]
Ki = Kp × 2π × SPEED_BW_HZ / SPEED_KI_RATIO [A/rad]
FF = (J/Kt) × 指令ランプの加速度 + friction_current × tanh(指令速度 / 境界層)
```

プラント Iq → ω = 1/((J/Kt)·s)。Ki は極零相殺ではなく**積分の折点を帯域の 1/SPEED_KI_RATIO に置く**設計。
FF は PID の出力に足し、飽和判定とアンチワインドアップは FF 込みで行う。

**帯域の上限**: 速度フィードバックは PLL オブザーバ (`PLL_OMEGA_N` = 900 rad/s) の遅れを通るので、
`SPEED_BW_HZ` = 20 Hz (位相余裕 約64°) 程度が実用上限。上げすぎても PLL の遅れで発振するだけ。
`output_limit` は外側ループが毎周期**上位指定のトルク上限 (`svc.iq_limit`)** に入れ替える。
アンチワインドアップ (バックカリキュレーション) がこの値を基準に働くので、飽和中は積分が伸びない。
位置モードの移動速度は torque_limit と負荷と PID ゲインで決まる。速すぎるときは `kd` を上げる
([SERIAL_PROTOCOL.md](SERIAL_PROTOCOL.md) 参照)。

### 逆起電力・dq干渉のフィードフォワード (`CURRENT_FF_ENABLE`)

`Vd -= ω_e·L·Iq`, `Vq += ω_e·L·Id + ω_e·ψm` を PI の出力に足す。応答が速度に依存しなくなり (モデル上 160 rad/s で 1.55 ms → 0.55 ms)、
積分項が電圧余裕を食わなくなる。FF 単独で変調限界を超えると PI が制御権限を失うので `CURRENT_FF_MAX_RATIO` (0.85) で頭打ちにする。
**符号を間違えると外乱が倍になる**。実機では `Vq(FF...)` を見て、FF が Vq と同符号で速度とともに大半を占めていれば正しい。

### 調整用の状態表示

`STATUS_PRINT_INTERVAL_S` を 0.5f 程度にすると、Iq の指令と実測、Id、Vd、Vq (FF 分) と変調限界、区間内の相電流ピーク、
エンコーダ統計、トルク制限、受信エラー数が出る。0 なら関数ごと消えるので常用時のコストはゼロ。

```
Iq: +0.21/ +0.21A  Id: +0.00A  Vd:+0.01V  Vq:+0.22(FF+0.10)/ 3.55V  peak: 0.76A   10.3rad/s  ...
```

`peak` は生の相電流の最大値で、PWM リプルを含むため dq 電流の数倍になるのが正常。

## 停止時はコースト (短絡制動にしない)

`enable = false` のときは **MOE を落として全FETをOFF** にする (`BLDC_SetOutputEnable(false)`)。

全相デューティ0.5は線間電圧こそ0だが、3相の端子が常に同電位で振られる = モータ3相の短絡と同じ状態になる。
回転中は逆起電力が `I ≈ E / |R + jω_e L|` の短絡電流を流して短絡制動になり、**過電流保護が働いた直後に一番電流を流したくない場面で
一番電流が流れる**という逆転が起きる。

MOE=0 で正しくコーストさせるには BDTR の **OSSI=1** が要る (CubeMX 既定は `TIM_OSSI_DISABLE`。OSSI=0 だと出力ピンが Hi-Z になり DRV8300 の入力が浮く)。
OSSI=1 かつ `OISx / OISxN = 0` (tim.c の `TIM_OCIDLESTATE_RESET`) なら、MOE=0 で INH/INL がどちらも Low に固定され上下FETともOFFになる。
`tim.c` は CubeMX の再生成で上書きされるので、センター揃えの設定と OSSI は `BLDC_InitPwmTimer` で立てている。

短絡制動を使いたい場合は `BLDC_MODE_BRAKE` の中で明示的に行うこと。停止・保護のデフォルトにしてはいけない。

## 保護

- **過電流**: `OVERCURRENT_LIMIT` (15 A) を `OVERCURRENT_TRIP_COUNT` (5) サンプル連続で超えたら `enable = false` にしてラッチし、
  その瞬間の状態を `BLDCTripInfo` に記録する。判定はローパス前の生値。ラッチ中は `BLDC_XxxControl()` を呼んでも起動せず、
  `BLDC_ClearOvercurrent()` で解除 (app ではスイッチを押すと解除)。この基板にはハードの過電流保護が無く、短絡のような急峻な故障には間に合わない。
- **過熱**: `TEMP_LIMIT` (60 °C) 超でラッチ。復帰は 5 °C 下がったとき。
- **電源電圧**: `SUPPLY_VOLTAGE_MIN/MAX_LIMIT` (7〜15 V) の範囲外が `SUPPLY_VOLTAGE_TRIP_DELAY_MS` (500 ms) 連続したときだけ停止してラッチ。
  復帰は範囲の内側に `SUPPLY_VOLTAGE_RECOVER_HYST` (0.5 V) 戻ったとき。
- **無通信**: `SERIAL_TIMEOUT_S` (0.5 s) で停止モード。トルク制限も 0 に戻る。
- **トルク制限**: 上位が何を送っても Kt × `MAX_CURRENT` で頭打ちにし、起動直後と通信断のあとは 0 (動かない)。

異常は赤LEDの点滅回数で通知する (1回: 過熱、2回: 電圧異常、3回: 過電流)。
