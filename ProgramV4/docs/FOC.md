# FOC (ベクトル制御) の構成

## ファイル構成

| ファイル | 役割 |
|---|---|
| `src/bldc/current_sense.c/h` | PWM 同期のローサイドシャント電流計測 (ADC1 + DMA) |
| `src/bldc/foc.c/h` | Clarke / Park / 逆Park / SVPWM / 電流PI などの数学部分 |
| `src/bldc/bldc.c/h` | 制御ループ本体と app 向けの API |
| `src/app/app.c/h` | シリアル通信・LED・スイッチ・保護判定のみ |
| `src/app/config.h` | 全パラメータ |

`app` にはモーター制御そのものは書かない。app がやるのは
`BLDC_SetSupplyVolt()` でセンサ値を渡すことと、`BLDC_XxxControl()` で目標値を指示することだけ。

## 制御の流れ

```
TIM1 (20 kHz, センター揃えアップダウンカウント, ARR=1800)
  │  上りで CNT = 1750 (頂点の50カウント手前) を通過 → OC4REF 立ち上がり → TRGO2
  │  低側FETのON区間は頂点を中心に広がるので、ここが区間の中央 = 平均電流が取れる
  ↓
ADC1 が U相/V相 の電流を1点サンプリング (平均ではない)
  ↓ DMA転送完了割り込み  ← ここが制御ループのタイミング
HAL_ADC_ConvCpltCallback()   [bldc.c]
  ├─ BLDC_UpdateEncoder()        20 kHz : 角度追従オブザーバ(2次PLL)
  │                                       → 機械角と角速度を同時に更新
  ├─ BLDC_CalculateAngularAccel()   50 Hz
  ├─ BLDC_OuterLoop()             1 kHz : 速度/位置PID → Iq指令 [A]
  └─ BLDC_CurrentLoop()          20 kHz :
        電流取得 → 過電流判定 → 電気角 sin/cos
        → Clarke → Park → Id/Iq の PI 制御
        → 電圧ベクトルの円制限 (+アンチワインドアップ)
        → 逆Park → SVPWM → CCR1/2/3 書き込み
```

## 割り込み優先度

20 kHz の制御ループを最優先にしてジッタを抑えている (`CurrentSense_Init` 内で設定)。

| 割り込み | 優先度 |
|---|---|
| DMA1_Channel1 (ADC1 = 制御ループ) | 0 |
| SysTick | 1 |
| DMA1_Channel4-7 (UART) | 2 |
| DMA1_Channel2 (ADC2) | **無効化**。値は DMA が勝手に更新するので割り込み不要 |

## 実行時間

-Og ビルドで毎周期およそ 750 命令 (HAL の DMA 割り込み処理を除く)。
72 MHz で約 14〜16 µs、周期 50 µs に対して **CPU 使用率 28〜32% 程度**。
角度追従オブザーバを 20 kHz で回すぶん、500 Hz の速度計算だった頃より
1周期あたり 1〜2 µs 増えている。

高速化のために以下をしている。割り込みの中を触るときは壊さないこと。

- **倍精度演算を作らない**。`mymath.h` の `PI` / `TWO_PI` は `double` リテラルなので、
  単精度FPUしか無い Cortex-M4 では式全体がソフトウェアエミュレーションに落ちる。
  割り込みの中では `foc.h` の `PI_F` / `TWO_PI_F` / `FOC_NormalizeRadians()` /
  `FOC_AngleDiff()` を使う。定数リテラルには必ず `f` を付ける。
- **sin/cos は `FOC_SinCos()`**。CMSIS-DSP の 512点テーブル `sinTable_f32` を直接引き、
  範囲縮約と補間係数を1回で済ませて sin と cos を同時に返す
  (`arm_sin_f32` / `arm_cos_f32` を別々に呼ぶと縮約が2回走るので使っていない)。
  強制転流 (`BLDC_OpenLoopDrive`) もこれを使う。sin/cos の実装はプロジェクト内で
  この1つだけにしてあるので、`mymath.h` に三角関数を足さないこと。
- **PWM 出力は `TIM1->CCRx` を直接書く**。`PwmOut_Write` は `__HAL_TIM_SET_COMPARE` の
  チャンネル判定 switch が展開されて1相あたり約100命令になる。
- **平方根は `FOC_Sqrt()` (VSQRT.F32 一命令)**。libm の `sqrtf` は errno / NaN 処理で
  関数呼び出しが2段挟まる。
- エンコーダのラジアン変換係数は初期化時に事前計算 (毎回の除算を避ける)。

`arm-none-eabi-objdump -d build/ProgramV4.elf` で割り込み配下の関数に
`__aeabi_*` (倍精度) の呼び出しが無いことを確認できる。

## 変調とデューティ上限

SVPWM は min-max 方式 (三次高調波重畳)。3相の最大値と最小値の中点を全相から引くことで、
線間電圧を変えずに相電圧のピークを下げ、母線電圧の利用率を単純な正弦波変調の 2/√3 (約15%) 倍にする。

ただしローサイドシャントの都合で `MAX_DUTY = 0.88` に制限しているため、
出せる相電圧振幅は `(0.88 - 0.5) × 2/√3 = 0.439 × Vdc` まで
(理論上限は 0.577 × Vdc)。`MAX_MODULATION_RATIO` がこれ。

エッジ揃えだった頃は低側 ON 区間の後ろ側しか使えず `MAX_DUTY = 0.80` (変調率 0.346)
だったが、センター揃えにして区間が頂点の両側に分散したので 0.88 まで引けた。
経緯は [OPTIMIZATION.md](OPTIMIZATION.md) を参照。

もっと電圧を出したくなったら、以下のどれかが必要:

1. **アンプの整定時間を実測して `CURRENT_SENSE_SETTLING_COUNTS` を詰める**。
   いまの 144 カウント (2.0 µs) はデータシートからの保守的な見積もりで、
   実測していない。ADC のトリガ位置をスイープすれば MCU だけで測れる
   (手順は [OPTIMIZATION.md](OPTIMIZATION.md))。実測すれば 0.92 程度まで見込める
2. ADC のサンプリング時間を 61.5 → 19.5 cycles に短縮する
   (INA181 の出力インピーダンスは低いので足りるはずだが、基板の RC フィルタ次第)
3. デューティが高い相の電流を推定で補う (相電流再構成)

## 電気角の合わせ方

エンコーダ校正 (`BLDC_SetEncoder`) は、電気角0の位置にロータを引き込んだときの
機械角を `encoder_offset_theta` として保存する。そのため校正後は

```
elec_theta = mech_theta * POLE_PAIRS   (d軸 = ロータ磁束方向)
```

がそのまま Park 変換の角度になる。`config.h` の `ELEC_THETA_OFFSET` は通常 0。

**確認方法**: 無負荷でトルク制御 (Iq指令) を入れたとき、
`BLDC_GetId()` が 0 付近に留まり `BLDC_GetIq()` が指令に追従していれば合っている。
Id に大きな値が出るなら `ELEC_THETA_OFFSET` がずれている。

## エンコーダ周りではまった点 (実機で解決済み)

機械角の誤差は**極対数倍(7倍)されて電気角の誤差になる**。機械角がほんの少し
おかしいだけで電流制御が大きく乱れるので、ここは特に慎重に扱うこと。

### 起動時に機械角を実測値で確定させる (`encoder_primed`)

`mech_theta` を 0 から始めてローパスで実角度に収束させると、その約1msの間に
電気角が数回転してしまい、電流制御が完全に破綻する。

- 症状: 起動直後だけ相電流が 8A 近くまで跳ね、トルクモード(指令が即座に立ち上がる)では
  過電流保護が発動していた。速度モードは指令がゆっくり立ち上がるので発症しにくかった。
- 対策: `BLDC_UpdateEncoder` の初回はフィルタを通さず `mech_theta = theta` とする。
  `BLDC_Init` でも制御ループを回す直前に一度呼んで確定させている。

### 角度追従オブザーバ (2次PLL) — 速度の微分をやめた

**症状**: トルク制御は非常に滑らかなのに、速度制御だと**機械1回転ごとに「がくっがくっ」**となる。

**切り分け**: 電流ループ・電気角・SVPWM は両モードで共通。トルク制御が滑らかなら
それらは正常で、犯人は速度制御だけが使う `angular_speed` の**推定値**。
周期が機械1回転 = エンコーダの 0/2π の継ぎ目。

**原因**: 継ぎ目で2段階の事故が起きていた。

1. **速度がゼロに落ちる** — AS5600 のアナログ出力はレール付近で飽和する。校正で記録した
   `max_encoder_val` はその飽和した値なので、継ぎ目の手前の数度は実際に回っても ADC 値が
   変わらない。角度が凍結 → 測定速度 0。
2. **見かけ上の超高速回転** — 飽和を抜けた瞬間、溜まった角度差が一気に現れる。旧実装の
   ステップリミッタ (`ENCODER_MAX_STEP_RAD` = 0.04 rad/50µs) はこれを小分けにして流したが、
   その傾きは **800 rad/s 相当**。旧 `BLDC_CalculateAngularSpeed()` はそれをそのまま微分した。

目標 10 rad/s のとき、測定速度が 0 → 121 rad/s まで振れ、`kp = 0.25` で
Iq 指令が **−8 A (上限)** に張り付く。「加速 → フルブレーキ」を1回転ごとに食らっていた。
トルク制御が無傷なのは、継ぎ目での**角度**誤差は数百µsで解消する程度で体感できないから。

**対策**: 微分をやめ、推定角 θ̂ を観測角に追従させる制御ループ (2次PLL) を回して、
その内部状態として θ̂ と ω̂ を**同時に**得る。

```
e   = θ_meas - θ̂                (イノベーション)
ω̂ += PLL_KI * e * dt            (速度推定 = 積分器)
θ̂ += (ω̂ + PLL_KP * e) * dt      (角度推定)
```

閉ループは `θ̂/θ_meas = (KP·s + KI)/(s² + KP·s + KI)` の標準2次系。
`ω_n = √KI`, `ζ = KP/(2√KI)`。ζ=1 (臨界制動)、ω_n = 200 rad/s に設定 (`config.h`)。

微分ではなく**積分**で速度を作るので、以下が同時に得られる。

| | 微分 + ローパス (旧) | 2次PLL (新) |
|---|---|---|
| 量子化ノイズ | 微分が高周波を持ち上げる | 積分器なので平滑 |
| 等速回転での遅れ | ローパスのぶん位相が遅れる | **定常誤差ゼロ** |
| 観測の欠測 | そのまま速度スパイクになる | ω̂ で外挿して乗り切る |

3つ目が今回の直接の対策。あわせて観測値のゲートを2種類入れてある。

- **飽和検出**: 生の ADC 値がレール付近 (`ENCODER_EDGE_MARGIN_LSB`) なら角度情報が無いので棄却。
  校正で記録した min/max が飽和値そのものなので、端に張り付いたサンプルを弾けば飽和域を正確に捕まえられる。
- **グリッチ検出**: イノベーションが `ENCODER_INNOVATION_LIMIT_RAD` を超えたら棄却。
- 棄却中は補正せず ω̂ による外挿 (デッドレコニング) のみ。

この2つのゲートの扱いを分けることが**必須**。詳細は下の「ロックが戻らなくなった話」を参照。

これに伴い `SPEED_CALC_DIV` / `SPEED_LPF` / `K_ENC_LPF` (速度依存のローパス切り替え) は
**すべて不要になって削除した**。3つのその場しのぎのフィルタが1つの原理的な推定器に置き換わっている。

**確認方法**: `STATUS_PRINT_INTERVAL_S` を 0.5f にすると継ぎ目の状態が3つ出る。

| 表示 | 意味 | 読み方 |
|---|---|---|
| `sat:` | 飽和で棄却したサンプル数 | 1回転あたり数十〜数百なら AS5600 が飽和している (正常な検出)。0 ならリデュースドレンジで飽和が無い |
| `glt:` | イノベーション過大で棄却したサンプル数 | 継ぎ目の遷移グリッチのぶん。`ENCODER_GLITCH_MAX`(=20) の倍数に近い値が1回転ごとに出る |
| `emax:` | 採用したイノベーションのピーク [rad] | **継ぎ目の段差の大きさそのもの**。0.01 程度なら校正良好。0.05 を超えるなら `encoder_scale` の精度不足 |

`emax` が大きいときは、観測器のゲインをいじるのではなく**エンコーダ校正をやり直す**のが正しい対処。
`sat` が 0 なのに `glt` が多い場合は、飽和が無いタイプなので継ぎ目の遷移が
`ENCODER_GLITCH_MAX` (1ms) で渡り切れているかを確認する。

### ロックが戻らなくなった話 (実機で解決済み)

**症状**: トルク制御で回しているロータを手で止めると、離しても復帰せず脱調したような
動きのままになる。**手でもう一度回してやると直る**。

**原因**: オブザーバ導入時の棄却ロジックに2つの設計ミスがあった。

1. **「観測できない」と「推定がずれている」を混ぜて棄却していた。**
   手で急停止させると θ̂ は ω̂ のまま自走を始める。すると θ_meas と θ̂ の差
   (イノベーション) が大きくなるが、旧実装はこれを「異常な観測」と判定して棄却した。
   棄却するとイノベーションが ω̂ に入らないので ω̂ が補正されず、θ̂ はさらに自走する。
   **自分の誤差を理由に自分を補正しない**という自己維持ループになっていた。
   θ̂ が自走して θ_meas を追い越す瞬間だけイノベーションが小さくなり、そこで連続棄却
   カウンタがリセットされるため、上限による自己復帰も働かなかった。
   手で回すと θ_meas が θ̂ に一致する点を通り、そこでロックを取り戻して復帰していた。

2. **積分パスのイノベーションに上限をかけていた。** `dω̂/dt` が `PLL_KI × 上限値` で
   頭打ちになる。手で止めたときの減速は数千 rad/s² あるのに、この制限は
   数百 rad/s² しか許さないので、原理的に追従できなかった。

**対策**:

- 飽和 (生のADC値で「観測できない」と確実に分かる) は長め (50ms) に外挿してよい。
- イノベーション過大は、グリッチが短いことを利用して 1ms だけ様子を見る。それでも
  続くならグリッチではないので**棄却をやめ、全量をPLLに通して再ロックさせる**。
- **積分パスの制限は「ロック中のみ」適用する** (`PLL_SPEED_ERROR_LIMIT_RAD`)。
  最初は制限を丸ごと撤廃したが、それだと継ぎ目の段差が全量 ω̂ に入り、
  1回転ごとに Iq がスパイクして LED が光る症状が残った。正しい使い分けは
  **「ロック中は疑い、ロックを失っていたら信じる」**。
  ゲート(b)が「グリッチではない = 推定が本当にずれている」と判定した状態
  (`encoder_glitch_count` が上限に張り付いている) が、そのまま再取得中の判定になる。

**教訓**: 推定器の「外れ値を弾く仕組み」は、推定器自身がずれたときに
**自分のずれを外れ値と誤認しうる**。棄却には必ず打ち切り条件を付け、
「観測が悪いのか推定が悪いのか」を判定できる材料 (今回は生のADC値) で分岐すること。

**再ロックの速さ**: 大きな周波数誤差からの引き込み範囲はおよそ `PLL_KP` で決まる。
`PLL_KP = 2·ω_n ≥ MAX_ANGULAR_SPEED` を満たしていれば、どの運転速度から急停止しても
数十msで再ロックする。`PLL_OMEGA_N` を下げるときはこの条件を割らないこと。

### 校正中はスルーレート制限を切る (`encoder_primed`)

`BLDC_SetEncoder` のオフセット測定は、極対数ぶん (7回) ロータを電気角1回転ずつ送りながら
「電気角0に引き込んだときの機械角」を平均する。このとき **測定ループの直前で
`encoder_primed = false` にして `mech_theta` を実測値に張り直す**必要がある。

理由: 直前の位相送りでロータは機械角で 2π/7 ≒ 0.9 rad 動いているが、
`BLDC_UpdateEncoder` のスルーレート制限 (`ENCODER_MAX_STEP_RAD` × ローパス) は
1呼び出しあたり 0.01 rad 程度しか進めない。校正ループは `HAL_Delay(1)` なので
追いつくのに約90ms かかり、200サンプルの平均のうち最初の半分近くが
「追従中のランプ」になる。これは 0.2 rad(機械角) ≒ **70°(電気角)** のオフセット誤差になる。

なお、測定点は機械角で 2π/7 ずつ離れているが**そのまま平均してよい**。

```
測定値 v_k = (θ0 + k・2π/P) mod 2π       (k = 0..P-1)
平均      = θ0 + (2π/P)・((P-1)/2 - M)   (M: 2πを跨いだ回数)
```

平均は θ0 と `2π/P` の整数倍しか違わず、電気角は機械角を P 倍して 2π で折り返すので
`2π/P` のずれは電気角では 2π のずれ = 同一。ただしこの相殺は
**各測定値が等間隔かつ同じ誤差を持つ**ことが前提なので、上のように特定の周回だけ
誤差が乗ると成り立たなくなる。

### アナログ出力の盲点とスケール補正 (実測で確定)

AS5600 のアナログ出力はレール付近で飽和するため、**1回転あたり角度が読めない区間 (盲点) が存在する**。
実機で測ると次の通りだった。

```
Iq: +0.35/ +0.36A  ...  19.2rad/s  sat: 110 glt:   1 emax:0.0876rad
                        20.1rad/s  sat: 215 glt:   1 emax:0.0895rad
```

`sat` が 108 と 216 を交互に出しているのが決め手。20 rad/s では 1回転 = 314 ms、
表示間隔 0.5 s なので 1.59 回転/表示 → 継ぎ目を1回または2回またぐ。
つまり**飽和域は1回転あたり 108 サンプル**。

```
108 × 50µs = 5.4ms  →  20 rad/s × 5.4ms = 0.108 rad (6.2°, 1周の1.7%)
```

**スケールの誤り**: 従来は `encoder_scale = 2π / (max - min)` としていたが、
ADC値 `[min, max]` が実際にカバーしているのは 2π ではなく **2π − 盲点幅**。
2π を割り当てると θ_meas が引き伸ばされる。

```
2π / (2π - 0.108) = 1.0173   (1.7%の引き伸ばし)
```

この結果、盲点を外挿で渡るとき θ̂ は `0.108 × 1.0173 = 0.110 rad` 進むのに対し
観測は元の位置から再開するので、**毎回転 0.11 rad の段差**ができる。
実測 `emax = 0.090 rad` はこれ (フィルタの遅れぶん小さく出る)。**この段差は速度に依存しない**
(`dead × 比率` で ω が約分される)。

**対策**: 校正時に盲点幅を実測し、スケールから差し引く。

```c
svc.encoder_scale = (TWO_PI_F - svc.encoder_dead_zone) / range;
```

盲点幅は `BLDC_SetEncoder` の2周目のスキャンで測る。等速で回しながら
「レール付近に張り付いていたサンプルの割合」を数えると、等速なので
**時間の割合＝機械角の割合**になり、そのまま角度幅が求まる。
測定値はフラッシュに保存する (`BLDCFlashData`)。

**注意**: `ENCODER_INNOVATION_LIMIT_RAD` は実測 `emax` より十分大きくすること。
当初 0.10 に対し実測 0.090 とマージンが1割しかなく、`glt` が時々 1〜2 出ていた。
20サンプル連続で超えると再取得モードに入り、積分パスの制限が外れて
速度スパイクが復活する。現在は 0.25 (約2.7倍の余裕)。

### フラッシュ校正値のフォーマット

項目を追加/変更したら `BLDC_FLASH_MAGIC` も必ず変えること。旧フォーマットのデータを
新フォーマットとして読むと、追加した項目にゴミが入って静かに誤動作する
(盲点幅にゴミが入れば角度が丸ごと狂う)。マジックが合わなければ安全な既定値に落ちて
「校正してください」と警告が出る。

### 根本対策 (次の基板)

CurcuitV4 は AS5600 の SDA/SCL が未接続でアナログ出力しか使えない。
I²C を繋げば 12bit のデジタル角度を直接読めるので、アナログ出力の飽和・ノイズ・
遷移グリッチの問題がまとめて消える。

なお **OUT ピンにコンデンサを足すのは逆効果**。遷移が緩やかになって中間値を拾う
サンプルが増えるうえ、位相遅れがそのまま電気角の誤差になる。

## ゲイン調整

### 電流PI (`CURRENT_PI_KP` / `CURRENT_PI_KI`)

```
Kp = L × 2π × f_bw     [V/A]
Ki = R × 2π × f_bw     [V/(A·s)]
```

L: 相インダクタンス [H]、R: 相抵抗 [Ω]、f_bw: 目標帯域 [Hz]。
f_bw は PWM 周波数の 1/10〜1/20 (20 kHz なら 1〜2 kHz) が上限の目安。
実測値が分からないうちは低めから始めて、電流が振動しない範囲で上げる。

### 速度/位置PID

**出力の単位が電圧 [V] から電流 [A] に変わっている**ので、V3 までのゲインはそのままでは使えない。
`svc.speed_pid` / `svc.position_pid` の `output_limit` は `MAX_CURRENT`。

### 調整用の状態表示

`config.h` の `STATUS_PRINT_INTERVAL_S` を 0.5f 程度にすると、Iq の指令と実測、Id、
Vq と変調限界、区間内の相電流ピークが printf で出る。

```
Iq: +0.21/ +0.21A  Id: +0.00A  Vq:+0.22/ 3.55V  peak: 0.76A   10.3rad/s  10.2V 31C
```

0.0f にすると条件がコンパイル時に畳まれて関数ごと消えるので、常用時のコストはゼロ。
`peak` は生の相電流の最大値で、PWMリプルを含むため dq 電流の数倍になるのが正常
(過電流しきい値はこれを見て決めた)。

## 停止時はコースト (短絡制動にしない)

`enable = false` のときは **MOE を落として全FETをOFF** にする (`BLDC_SetOutputEnable(false)`)。

以前は全相デューティ0.5にしていたが、これは線間電圧こそ0でも **3相の端子が常に同電位で
振られる = モータ3相を短絡している**のと同じ状態になる。止まっていれば無害だが、
回転中は逆起電力が

```
I ≈ E / |R + jω_e L|
```

の短絡電流を流すので短絡制動になる。**過電流保護が働いた直後に、一番電流を流したくない
場面で一番電流が流れる状態に入る**という逆転が起きていた。

MOE=0 で正しくコーストさせるには、BDTR の **OSSI=1** が要る (CubeMX の既定は
`TIM_OSSI_DISABLE`)。OSSI=0 だと出力ピンが Hi-Z になり、DRV8300 の入力が浮いてしまう。
OSSI=1 かつ `OISx / OISxN = 0` (tim.c の `TIM_OCIDLESTATE_RESET`) なら、
MOE=0 のとき INH/INL がどちらも Low に固定され、上下FETともOFFになる。
`tim.c` は CubeMX の再生成で上書きされるので、OSSI は `BLDC_Init` の中で
`TIM1->BDTR |= TIM_BDTR_OSSI;` として立てている。

短絡制動を使いたい場合は `BLDC_MODE_BRAKE` の中で明示的に行うこと。
停止・保護のデフォルトにしてはいけない。

## 保護

- `OVERCURRENT_LIMIT` を超えると即座に `enable = false` にしてラッチする。
  検出遅れを避けるため、判定はローパスをかける**前**の生値で行う。
- ラッチ中は `BLDC_XxxControl()` を呼んでも起動しない。`BLDC_ClearOvercurrent()` で解除。
  app 側ではスイッチ (PA12) を押すと解除される。
- フラッシュのエンコーダ校正値が未書き込み/不正なときは、0除算で NaN が伝播しないよう
  安全なデフォルトに落として警告を出す。

## シリアルプロトコルの変更点

トルク指令とブレーキ指令の**単位が電圧 [V] から電流 [A] に変わった**。

| モード | ヘッダ | ペイロード (int16) | 単位 |
|---|---|---|---|
| 角速度制御 | 0xFE | ×0.01 | rad/s |
| 位置制御 | 0xFD | ×0.001 | rad |
| トルク制御 | 0xFC | **×0.001** | **A** (旧: ×0.0001 で V) |
| ブレーキ | 0xFB | **×0.001** | **A** (旧: ×0.0001 で V) |

送信フレームは 10 バイト → **12 バイト**に拡張し、q軸電流 [mA] (int16) を追加した。

```
[0] 0xFF
[1] フラグ: bit3=過電流 bit2=過熱 bit1=電圧異常 bit0=動作中
[2] 温度 [°C]
[3-4] 機械角 × 10000
[5-6] 角速度 × 100
[7-8] 角加速度 × 10
[9-10] q軸電流 [mA]      ← 追加
[11] 0xAA
```

ControllerApp 側も合わせて直すこと。
