# FOC (ベクトル制御) の構成

## ファイル構成

| ファイル | 役割 |
|---|---|
| `src/bldc/current_sense.c/h` | PWM 同期のローサイドシャント電流計測 (ADC1 + DMA) |
| `src/bldc/foc.c/h` | Clarke / Park / 逆Park / SVPWM / 電流PI などの数学部分 |
| `src/bldc/bldc.c/h` | 制御ループ本体と app 向けの API |
| `src/app/app.c/h` | シリアル通信・LED・スイッチ・保護判定のみ |
| `src/app/config.h` | 全パラメータ |

`app` にはモーター制御そのものは書かない。app がやるのは
`BLDC_SetSupplyVolt()` でセンサ値を渡すことと、`BLDC_XxxControl()` で目標値を指示することだけ。

## 制御の流れ

```
TIM1 (20 kHz, エッジ揃えUPカウント, ARR=3599)
  │  CNT = 3200 で OC4REF 立ち上がり → TRGO2
  ↓
ADC1 が U相/V相 の電流を1点サンプリング (平均ではない)
  ↓ DMA転送完了割り込み  ← ここが制御ループのタイミング
HAL_ADC_ConvCpltCallback()   [bldc.c]
  ├─ BLDC_UpdateEncoder()        20 kHz : 機械角の取得とローパス
  ├─ BLDC_CalculateAngularSpeed()  500 Hz
  ├─ BLDC_CalculateAngularAccel()   50 Hz
  ├─ BLDC_OuterLoop()             1 kHz : 速度/位置PID → Iq指令 [A]
  └─ BLDC_CurrentLoop()          20 kHz :
        電流取得 → 過電流判定 → 電気角 sin/cos
        → Clarke → Park → Id/Iq の PI 制御
        → 電圧ベクトルの円制限 (+アンチワインドアップ)
        → 逆Park → SVPWM → CCR1/2/3 書き込み
```

## 割り込み優先度

20 kHz の制御ループを最優先にしてジッタを抑えている (`CurrentSense_Init` 内で設定)。

| 割り込み | 優先度 |
|---|---|
| DMA1_Channel1 (ADC1 = 制御ループ) | 0 |
| SysTick | 1 |
| DMA1_Channel4-7 (UART) | 2 |
| DMA1_Channel2 (ADC2) | **無効化**。値は DMA が勝手に更新するので割り込み不要 |

## 実行時間

-Og ビルドで毎周期およそ 655 命令 (HAL の DMA 割り込み処理を除く)。
72 MHz で約 12〜14 µs、周期 50 µs に対して **CPU 使用率 25〜28% 程度**。

高速化のために以下をしている。割り込みの中を触るときは壊さないこと。

- **倍精度演算を作らない**。`mymath.h` の `PI` / `TWO_PI` は `double` リテラルなので、
  単精度FPUしか無い Cortex-M4 では式全体がソフトウェアエミュレーションに落ちる。
  割り込みの中では `foc.h` の `PI_F` / `TWO_PI_F` / `FOC_NormalizeRadians()` /
  `FOC_AngleDiff()` を使う。定数リテラルには必ず `f` を付ける。
- **sin/cos は CMSIS-DSP の `arm_sin_f32` / `arm_cos_f32`** (512点テーブル+線形補間)。
  `mymath.h` の `Sin`/`Cos` は1度刻みなので Park 変換には粗すぎる。
- **PWM 出力は `TIM1->CCRx` を直接書く**。`PwmOut_Write` は `__HAL_TIM_SET_COMPARE` の
  チャンネル判定 switch が展開されて1相あたり約100命令になる。
- **平方根は `FOC_Sqrt()` (VSQRT.F32 一命令)**。libm の `sqrtf` は errno / NaN 処理で
  関数呼び出しが2段挟まる。
- エンコーダのラジアン変換係数は初期化時に事前計算 (毎回の除算を避ける)。

`arm-none-eabi-objdump -d build/ProgramV4.elf` で割り込み配下の関数に
`__aeabi_*` (倍精度) の呼び出しが無いことを確認できる。

## 変調とデューティ上限

SVPWM は min-max 方式 (三次高調波重畳)。3相の最大値と最小値の中点を全相から引くことで、
線間電圧を変えずに相電圧のピークを下げ、母線電圧の利用率を単純な正弦波変調の 2/√3 (約15%) 倍にする。

ただしローサイドシャントの都合で `MAX_DUTY = 0.80` に制限しているため、
出せる相電圧振幅は `(0.80 - 0.5) × 2/√3 = 0.346 × Vdc` まで
(理論上限は 0.577 × Vdc)。`MAX_MODULATION_RATIO` がこれ。

もっと電圧を出したくなったら、以下のどれかが必要:

1. `CURRENT_SENSE_TRIG_POINT` を ARR 側に寄せて `MAX_DUTY` を上げる (整定時間との勝負)
2. TIM1 をセンターアライン (アップダウンカウント) にして、谷で2回サンプリングする
3. デューティが高い相の電流を推定で補う (相電流再構成)

## 電気角の合わせ方

エンコーダ校正 (`BLDC_SetEncoder`) は、電気角0の位置にロータを引き込んだときの
機械角を `encoder_offset_theta` として保存する。そのため校正後は

```
elec_theta = mech_theta * POLE_PAIRS   (d軸 = ロータ磁束方向)
```

がそのまま Park 変換の角度になる。`config.h` の `ELEC_THETA_OFFSET` は通常 0。

**確認方法**: 無負荷でトルク制御 (Iq指令) を入れたとき、
`BLDC_GetId()` が 0 付近に留まり `BLDC_GetIq()` が指令に追従していれば合っている。
Id に大きな値が出るなら `ELEC_THETA_OFFSET` がずれている。

## エンコーダ周りではまった点 (実機で解決済み)

機械角の誤差は**極対数倍(7倍)されて電気角の誤差になる**。機械角がほんの少し
おかしいだけで電流制御が大きく乱れるので、ここは特に慎重に扱うこと。

### 起動時に機械角を実測値で確定させる (`encoder_primed`)

`mech_theta` を 0 から始めてローパスで実角度に収束させると、その約1msの間に
電気角が数回転してしまい、電流制御が完全に破綻する。

- 症状: 起動直後だけ相電流が 8A 近くまで跳ね、トルクモード(指令が即座に立ち上がる)では
  過電流保護が発動していた。速度モードは指令がゆっくり立ち上がるので発症しにくかった。
- 対策: `BLDC_UpdateEncoder` の初回はフィルタを通さず `mech_theta = theta` とする。
  `BLDC_Init` でも制御ループを回す直前に一度呼んで確定させている。

### 角度の変化量リミッタ (`ENCODER_MAX_STEP_RAD`)

AS5600 のアナログ出力が 0/2π を跨ぐ瞬間、ADC が遷移中の中間値を 1 サンプルだけ拾うことがある。
これが極対数倍された電気角の飛びになり、1回転に数回「カチッ」という異音が出ていた。
さらにその飛びは速度計算にも入り込み、「一瞬 300 rad/s で回った」と誤認させて
速度制御が逆向きの電流を出すため、音を増幅していた。

- 対策: ロータの慣性から、1制御周期(50µs)で動ける角度には物理的な上限がある。
  それを超える変化は頭打ちにする。`MAX_ANGULAR_SPEED` の4倍まで追従できる余裕を持たせてある。
- あわせて、高速域(50rad/s超)でフィルタを迂回して `mech_theta = theta` としていた分岐も
  リミッタを通る形に統合した (以前は高速域でグリッチが素通しだった)。

### 根本対策 (次の基板)

CurcuitV4 は AS5600 の SDA/SCL が未接続でアナログ出力しか使えない。
I²C を繋げば 12bit のデジタル角度を直接読めるので、アナログ出力の飽和・ノイズ・
遷移グリッチの問題がまとめて消える。

なお **OUT ピンにコンデンサを足すのは逆効果**。遷移が緩やかになって中間値を拾う
サンプルが増えるうえ、位相遅れがそのまま電気角の誤差になる。

## ゲイン調整

### 電流PI (`CURRENT_PI_KP` / `CURRENT_PI_KI`)

```
Kp = L × 2π × f_bw     [V/A]
Ki = R × 2π × f_bw     [V/(A·s)]
```

L: 相インダクタンス [H]、R: 相抵抗 [Ω]、f_bw: 目標帯域 [Hz]。
f_bw は PWM 周波数の 1/10〜1/20 (20 kHz なら 1〜2 kHz) が上限の目安。
実測値が分からないうちは低めから始めて、電流が振動しない範囲で上げる。

### 速度/位置PID

**出力の単位が電圧 [V] から電流 [A] に変わっている**ので、V3 までのゲインはそのままでは使えない。
`svc.speed_pid` / `svc.position_pid` の `output_limit` は `MAX_CURRENT`。

### 調整用の状態表示

`config.h` の `STATUS_PRINT_INTERVAL_S` を 0.5f 程度にすると、Iq の指令と実測、Id、
Vq と変調限界、区間内の相電流ピークが printf で出る。

```
Iq: +0.21/ +0.21A  Id: +0.00A  Vq:+0.22/ 3.55V  peak: 0.76A   10.3rad/s  10.2V 31C
```

0.0f にすると条件がコンパイル時に畳まれて関数ごと消えるので、常用時のコストはゼロ。
`peak` は生の相電流の最大値で、PWMリプルを含むため dq 電流の数倍になるのが正常
(過電流しきい値はこれを見て決めた)。

## 保護

- `OVERCURRENT_LIMIT` を超えると即座に `enable = false` にしてラッチする。
  検出遅れを避けるため、判定はローパスをかける**前**の生値で行う。
- ラッチ中は `BLDC_XxxControl()` を呼んでも起動しない。`BLDC_ClearOvercurrent()` で解除。
  app 側ではスイッチ (PA12) を押すと解除される。
- フラッシュのエンコーダ校正値が未書き込み/不正なときは、0除算で NaN が伝播しないよう
  安全なデフォルトに落として警告を出す。

## シリアルプロトコルの変更点

トルク指令とブレーキ指令の**単位が電圧 [V] から電流 [A] に変わった**。

| モード | ヘッダ | ペイロード (int16) | 単位 |
|---|---|---|---|
| 角速度制御 | 0xFE | ×0.01 | rad/s |
| 位置制御 | 0xFD | ×0.001 | rad |
| トルク制御 | 0xFC | **×0.001** | **A** (旧: ×0.0001 で V) |
| ブレーキ | 0xFB | **×0.001** | **A** (旧: ×0.0001 で V) |

送信フレームは 10 バイト → **12 バイト**に拡張し、q軸電流 [mA] (int16) を追加した。

```
[0] 0xFF
[1] フラグ: bit3=過電流 bit2=過熱 bit1=電圧異常 bit0=動作中
[2] 温度 [°C]
[3-4] 機械角 × 10000
[5-6] 角速度 × 100
[7-8] 角加速度 × 10
[9-10] q軸電流 [mA]      ← 追加
[11] 0xAA
```

ControllerApp 側も合わせて直すこと。
