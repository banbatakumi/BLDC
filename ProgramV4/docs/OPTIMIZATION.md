# ProgramV4 最適化メモ

FOC が動いたあとの「もっと良くする」作業の記録。着手順・結果・残課題。
パラメータの意味と根拠は `src/app/config.h`、制御の構成は [FOC.md](FOC.md)。

## 大前提: 制御周期も PWM 周波数も上げない

- 最高速度 `MAX_ANGULAR_SPEED = 150 rad/s` × `POLE_PAIRS = 7` = **電気角 167 Hz**
- 20 kHz PWM = 電気1周期あたり 120 サンプル。FOC の定石 (10〜20) の 10 倍近くある
- 電流リプル `ΔI_pp ≈ Vdc / (4·L·fsw)` ≈ 0.3 A_pp (L=0.5 mH で見積もり)。`MAX_CURRENT = 10 A` の 3% で問題にならない

電流ループは PWM 周期と 1:1 (デューティは 1 周期に 1 回しか更新できない) なので、速くするには PWM 周波数ごと上げるしかない。
しかし上げると (1) スイッチング損失が `fsw` に比例して増え、(2) **ローサイドシャントのサンプリング窓が絶対時間で縮み**
`MAX_DUTY` を下げるしかなくなって最高速度が落ちる。→ **20 kHz が最適点。**

## 残課題

### 7. エンコーダの継ぎ目

遅れ補償で連続的な角度ずれは消えたが、`emax` (継ぎ目の段差) が速度にほぼ依存せず残っている。

| 速度 | emax [rad] (機械角) | 電気角 |
|---|---|---|
| 20 rad/s | 0.11 〜 0.18 | 44〜72° |
| 120 rad/s | 0.03 〜 0.19 | 12〜76° |
| 247 rad/s | 0.03 〜 0.24 | 12〜96° |

(測定時点の値。0.05 rad 超は校正精度不足の目安)
1 回転に 1 回、電気角で最大 96° 飛ぶのでその瞬間 dq 変換が崩れ、`Vd` ±0.3 V、`Id` ±0.6 A のばらつきが出る。

根本対策 (I²C で AS5600 のフィルタを速くする) は CurcuitV4 では不可 (SDA/SCL 未接続)。V5 基板の課題。
ソフト側の候補:

1. エンコーダ校正のやり直し (スイッチを押しながら起動)。まず一番安い手
2. 飽和域を抜けたあとも数サンプル棄却を続け、センサ出力が整定してから PLL に戻す
3. 継ぎ目は機械角の固定位置に出るので補正テーブルを持つ (大がかり)

### 6 の残り

- **デッドタイム補償**: DTG = 20 → 278 ns (周期の 0.56%)。ψm 同定で Vq に 0.262 V の一定オフセットが見つかり
  (40 rad/s で Vq の 32%)、電流の向きで符号が反転するので Iq がゼロを跨ぐたびに 0.52 V 飛ぶ。低速トルクリプルの原因
- **位置制御の D 項**: 誤差の微分 + LPF をやめ、PLL の ω̂ をそのまま使う (`d_term = -kd * angular_speed`)
- **1.5 周期の演算遅れ補償**: 逆 Park 用の角度だけ `+ ω_e × 1.5 × CURRENT_LOOP_DT` 進める。入れれば電流帯域の上限が少し上がる
- **ADC2 のサンプリング時間**: [adc.c](../Core/Src/adc.c) の rank3 (TEMP) に `SamplingTime` を設定し直しておらず rank2 の 601.5 cycles が残り、
  スキャン 1 周が約 18 µs。PLL の帯域で平滑されるので優先度は低い
- **アンプ整定時間の実測** (下記 3 の「改善余地」)

## 2. ISR 実行時間の実測と 2b/2c

プロファイラの使い方は末尾。最初の実測で次の 3 つが分かった (**どれも事前の予想になかった**)。

```
[PROF] irq 10.82/23.83us (CPU 21.6/47.7%)  cb 18.57us  周期  2.11-47.92us  n=40000
```

### (a) 割り込みが 40 kHz で入っていた → 2b で修正

`n = 40000`、周期が 2.11 / 47.92 µs の 2 値。ADC1 の DMA は 2 変換なので 1 変換目の完了でハーフ転送 (HT) 割り込みが立ち、
空の `HAL_ADC_ConvHalfCpltCallback` を呼ぶためだけに毎回 1.04 µs 使っていた。
[current_sense.c](../src/bldc/current_sense.c) で `__HAL_DMA_DISABLE_IT(hadc1.DMA_Handle, DMA_IT_HT)` として止めた (TC 側には影響しない)。

### (b) 本当の CPU 使用率は 21.6% ではなく 43%

表示が「1 回あたりの時間 × **想定** 20 kHz」だったので、実レートが倍だったぶん半分に見えていた。
**想定周波数を使う計算は、想定が外れると静かに嘘をつく。** → 「合計サイクル数 ÷ 実経過時間」に変更し、実測レートも表示する。

### (c) ISR の時間は float の比較が食っている (→ 2c)

Cortex-M4F の float 比較は `VCMP.F32` + `VMRS APSR_nzcv, FPSCR` の 2 命令で、`VMRS` が FPU フラグをコアへ転送するためパイプラインを待たせ、
分岐込みで **1 回 8〜10 サイクル** (乗算・加算の 10 倍)。コールバック全体に 53 組あり約 6.6 µs、`cb` の 3 分の 1。
犯人は [mymath.h](../lib/mymath/mymath.h) の `Abs()` / `Constrain()` マクロ。

### 2c でやったこと

1. **`Abs()` を float では `VABS.F32` に**: C11 `_Generic` で型ごとに振り分け (`__builtin_fabsf`)。1 サイクル。マクロの 2 回展開問題も消えた
2. **`FOC_SinCos` の前の正規化を削除**: 内部で小数部を取るので入力範囲は任意。`mech_theta × 7` (最大 44 rad) を while で引いていたのは無駄だった
3. **`FOC_SinCos` を自前実装**: sin/cos を 1 回の縮約で取る (`cos(θ) = sin(θ + π/2)`、π/2 はテーブル 512 点のちょうど 128 点ぶん)。
   誤差は真値比 1.9e-5 (テーブル + 線形補間の限界、CMSIS と同等)
4. **デューティのクランプを整数比較に**: 3 相で 6 回の比較が 1 サイクルずつになる。`VCVT` は NaN を 0、範囲外を飽和させるので、
   変換後に整数でクランプすれば入力が何でも必ず範囲に収まる (float 比較だと NaN はすり抜けていた)

`vcmp`+`vmrs` が 21 組減り、約 170 サイクル ≈ 2.4 µs。

```
[PROF] irq 16.89/19.85us  CPU 33.8%  rate 20.00kHz  cb 14.68us  周期 49.90-50.10us
       内訳: PLL 3.79us  電流ループ 9.46/10.08us  外側 1.01us (1.00kHz)
```

| | 2b 前 | 2c 後 |
|---|---|---|
| CPU 使用率 | 43.3% | **33.8%** |
| 実測レート | 40.0 kHz | **20.00 kHz** |
| 周期のばらつき | 2.11-47.92 µs | **49.90-50.10 µs** |
| `cb` | 18.57 µs | **14.68 µs** |
| 電流ループ | 13.18 µs | **9.46 µs** |
| PLL | 4.06 µs | 3.79 µs |

PLL の比較 16 組は棄却ロジックの本体なのでこれ以上は削れない。残りを削るには演算そのものを減らすしかない。

## 2d (見送り): ホットパスを CCM RAM で実行

**やらない。33.8% / ピーク 19.85 µs で余裕が足りているため。** 最適化は「足りるまで」で止める。将来詰まったときのメモ:

- **HAL のディスパッチ約 1.5 µs (CPU 3%)**: `irq − cb` = 2.21 µs から計測自身のぶん (約 0.67 µs) を引いた値。
  `DMA1_Channel1_IRQHandler` → `HAL_DMA_IRQHandler` → `ADC_DMAConvCplt` → コールバックの経路。
  DMA 割り込みフラグを直接クリアして制御関数を呼ぶベアメタルのハンドラに置き換えれば消せる
- **フラッシュのウェイトステート**: 72 MHz は `FLASH_LATENCY_2`。プリフェッチは有効だが分岐のたびにバッファが無効になり、
  ホットパスには分岐が 40 個近くある。STM32F303 の CCM SRAM (4 KB) は I-bus 接続で命令フェッチでき、0 ウェイトで走る
- やるなら: (1) `startup_stm32f303x8.s` に `.ccmram` を FLASH (`_siccmram`) から CCM (`_sccmram`〜`_eccmram`) へコピーするループを追加
  (リンカスクリプト [STM32F303XX_FLASH.ld](../STM32F303XX_FLASH.ld) の `.ccmram` 定義は用意済み)、(2) ホットパスの関数に
  `__attribute__((section(".ccmram")))` を付ける
- サイズが厳しい: コールバック 2228 B + `BLDC_UpdateEncoder` 608 B + `FOC_SVPWM` 168 B + `FOC_LimitVoltageVector` 76 B + `CurrentSense_Read` 108 B ≈ 3.2 KB / 4 KB。
  HAL のディスパッチまで入れると溢れるので、ベアメタル化とセットになる

## 3. センター揃え PWM ✅

| | 変更前 | 変更後 |
|---|---|---|
| カウントモード | エッジ揃え UP | **センター揃え** (`CENTERALIGNED1`) |
| `PWM_ARR` | 3599 (`72M/(ARR+1)`) | **1800** (`72M/(2×ARR)`) |
| デューティ | `CCR/(ARR+1)` | **`CCR/ARR`** |
| ADC トリガ | `CCR4 = 3200` (区間の端) | **`CCR4 = ARR-50 = 1750`** (区間の中央) |
| `MAX_DUTY` | 0.80 | **0.88** |
| 変調率 | 0.346 | **0.439** (+27%) |

エッジ揃えでは低側 ON 区間 `[CCR, ARR]` の**後ろ側しか使えず**サンプリング点より手前のデューティしか出せなかった
(母線電圧の利用率が理論値 0.577 の 6 割)。センター揃えなら区間が頂点を中心に両側へ分散するので、同じ絶対時間の余裕で 0.88 まで引ける。

- タイマ設定は `tim.c` ではなく `BLDC_InitPwmTimer` で上書きする (`tim.c` は CubeMX の再生成で消えるため)
- 低側 ON 区間の中央でサンプリングするので、取れる値が三角波リプルの平均 = **その周期の平均電流**になる
  → `CURRENT_LPF_COEF` を緩められる (4 の前提)。3 相の立ち上がりが同時でなくなるのでリプルと EMI も下がる
- 設定の整合は `config.h` の `_Static_assert` で検査している (`MAX_DUTY_CCR` / `CURRENT_SENSE_TRIG_ADVANCE` /
  `CURRENT_SENSE_ACQ_COUNTS` / `PWM_ARR` のどれかを勘で触るとビルドが落ちる)。`MAX_DUTY` は整数の `MAX_DUTY_CCR` を正として定義している
  (`_Static_assert` は整数定数式しか受け付けず、ハードが比較するのもカウント数のため)

### 改善余地: アンプ整定時間の実測

`CURRENT_SENSE_SETTLING_COUNTS = 144` (2.0 µs) は INA181A1 の帯域 350 kHz (τ = 455 ns、1% 整定 = 4.6τ = 2.1 µs) からの
**保守的な見積もりで、実測していない**。実測すれば `MAX_DUTY` 0.92 (変調率 0.485、+40%) まで見込める。
オシロが無くても ADC 自体で測れる (未実施):

1. 開ループでロータを固定し、一定の直流電流を流す
2. `TIM1->CCR4` を低側 ON 直後から頂点までスイープ
3. 各点で電流を平均して記録
4. 低側 ON 区間内の真の電流は一定なので、読み値が変化している間は未整定。平らになった点が整定完了

デューティ 0.65 / 0.425 / 0.425 で駆動すれば U 相と V 相で低側 ON の時刻が違うので、1 回のスイープで 2 つの独立した測定が取れ相互検証になる。
制御ループが実際に通る経路 (シャント → INA181 → ADC サンプルホールド) そのものを測れるのが利点。

## 4. 電流ループの帯域 ✅

### 経緯

1. LPF を緩めた (`CURRENT_LPF_COEF` 0.25 → 0.5、fc 916 Hz → 2206 Hz)。3 でリプルがなくなったので不要になった遅れを減らす、単体で安全な変更
2. 最初の実測でステップ応答が 1 次系ではなく、速い成分 (リンギング約 2.5 kHz) と時定数 1.3 ms の長い尾に割れていた。
   閉ループの 2 極から逆算すると `R/L ≈ 2000〜3000 rad/s` だが、PI のゼロ点は `Ki/Kp = 1000 rad/s` で 3 倍ずれていた
   → **極とゼロが打ち消し合っていない**
3. Kp, Ki を同じ倍率で動かす方式 (旧 `CURRENT_BW_SCALE`) は `Ki/Kp = R/L` が成り立っている前提なので破棄。
   必要なのは倍率ではなく**比の修正**で、そのために L と R の実測が要る → `MEASURE_MOTOR_RL` を作り、
   `Kp = L·ω_bw`, `Ki = R·ω_bw` を実行時に計算する形にした

帯域の上限を決めるのは位相遅れ (700 Hz で 1.5 周期の演算遅れ 18.9° + 電流 LPF 17.6° → 位相余裕 約 53°)。

### 測定方法

**d 軸ステップ応答 (`MEASURE_CURRENT_STEP`)**: d 軸は磁束方向なのでトルクが出ずロータが動かず、逆起電力も負荷変動も混ざらない
電気的応答だけが取れる (SPM は Ld = Lq なので結果は q 軸に使える)。制御ループ自身が 20 kHz でサンプリングするので分解能 50 µs、オシロ不要。

- **63% 到達点は線形補間する**。補間なしだと τ を切り上げて帯域を過小評価する (合成波形で 1000 Hz の 1 次系が 796 Hz と出る。補間ありは 992 Hz)。
  63% 到達が 3 サンプルを切ると誤差が増えるので警告を出す
- **63% 点だけで時定数を語らない**。1 回目の測定は割れた応答の速いほうだけを拾って「1570 Hz」と報告してしまった。
  1τ / 2τ / 3τ を理想の 63.2 / 86.5 / 95.0% と比べる。判定の主役は **3τ**: 極零不一致だと 3τ でも 95% に届かない尾が残る
  (壊れていたとき 2τ +17% / 3τ −13%、直したあと +9% / +4%)。2τ が高めに出るのはループ内の遅れで異常ではない。
  `3τ < −8%` を主、`2τ > +20%` を従とした
- **検査のインデックスも補間する**。`(uint16_t)(k63f * m)` と切り捨てると手前の値を拾い、1τ が 51% と出て同じ応答でも通ったり落ちたりする

**L・R の同定 (`MEASURE_MOTOR_RL`)**: PI をバイパスして Vd を直接与えると素の 1 次系 (τ = L/R) になる。

- 電圧 2 点 (V と 2V) で `R = (V2−V1)/(I2−I1)`。デッドタイム (278 ns、12 V で約 0.067 V) の電圧損は一定なので消える
  (合成: 真値 0.300 Ω に対し 1 点法 +9.1%、2 点法 −0.0%)
- 開ループで電流を制限するものが無いので、`MOTOR_RL_ABORT_AMPS` 超過で ISR 内で即座に電圧を切る
- 63% 到達時間には電流 LPF (`−Ts/ln(1−a)` = 72 µs) と半周期 (25 µs。CCR はプリロード付きで、電流を拾うのは低側 ON 区間の中央) の遅れが混ざる。
  引かないと L を 4 割過大評価する (L が小さいほど効く。25 µH で +68%、45 µH で +37%)

### 結果 (2026-07-29)

```
V=0.400V → 定常 1.778A, 63%到達 0.311ms
V=0.800V → 定常 3.852A, 63%到達 0.295ms
→ R = 0.1928 Ω (1点法なら 0.2077)   L = 38 µH (補正なしなら 57 µH)   R/L = 5074 rad/s
```

デッドタイム損の逆算 0.057 V は事前見積もり 0.067 V と一致 (2 点法が効いている裏づけ)。
`Ki/Kp = 1000` に対し実際の `R/L` は 5074 で 5 倍ずれていた。新ゲインは Kp 0.203 (旧 0.75 の約 1/4)、Ki 1030 (旧 750)。
**Kp は下げるのが正解だった** (最初の見立てどおり 2〜3 倍にしていたら `Kp/L` が 9 kHz を超えて発振していた)。

| | 前 (Kp=0.75, Ki=750) | 後 (Kp=0.203, Ki=1030) |
|---|---|---|
| 95% 整定 | 2.1 ms | **0.50 ms** |
| 実測帯域 | 定義できない (2 つに割れる) | **714 Hz** |
| 挙動 | 1.045 まで行き 0.735 まで落ちる | 単調、オーバーシュート 1.7% |

### 設計値と実測値の乖離

`CURRENT_BW_HZ = 700` で実測 570 Hz だった (`ω_bw = Kp/L` は理想的な極零相殺と遅れ 0 を前提にするため、実測は 2〜3 割低く出る)。
比率で割り戻して `CURRENT_BW_HZ = 850` にしてある。**これは設計パラメータであって実測帯域ではない**。
「実際に達成したい帯域」は `CURRENT_BW_TARGET_HZ` (700) に分離してある
(実測を設計値に合わせようとすると、次はさらに高い値を要求する追いかけっこになるため)。上げるときは必ず `MEASURE_CURRENT_STEP` で確認する。

## 5. 逆起電力・dq 干渉フィードフォワード ✅

`Vd −= ω_e·L·Iq`, `Vq += ω_e·L·Id + ω_e·ψm` を PI の出力に足す。

### モデル検証 (L=38 µH, R=0.1928 Ω, Kp=0.2029, Ki=1030、Iq 2 A ステップの 95% 到達時間)

| 機械角速度 | FF 無し | FF 正しい | FF 符号ミス |
|---|---|---|---|
| 0 rad/s | 0.55 ms | 0.55 ms | 0.55 ms |
| 80 rad/s | 1.35 ms | **0.55 ms** | 1.55 ms |
| 160 rad/s | 1.55 ms | **0.55 ms** | **破綻** (10.3 A 偏差) |

正しい FF では応答が速度に依存せず、積分項も 0.39 V のまま (FF 無しは 160 rad/s で 4.87 V)。電圧の余裕を積分で食い潰さない。
効くのは速さと余裕で、定常精度ではない。**符号を間違えると打ち消すはずの項が二重に効く**。実機では `Vq(FF...)` を見る。

FF 単独で変調限界を超えると PI が制御権限を失う (ψm を過大見積もりしたとき、指令 +0.50 A に対し Iq が −0.24 A、ピーク 8 A)。
`CURRENT_FF_MAX_RATIO` (0.85) で頭打ちにしている。

### ψm の同定 (`MEASURE_MOTOR_PSI`) と結果

定常で `Vq = R·Iq + ω_e·ψm`。2 速度の差を取る (**ロータが回る**。開始前に 3 秒のカウントダウン)。FF が有効でも成立する。

```
40 rad/s → ω_e 280, Vq 0.824V, Iq 0.221A
80 rad/s → ω_e 560, Vq 1.356V, Iq 0.287A
→ ψm = 0.001854 Wb (1点法なら 0.002322、+25%)
```

検算: 無負荷到達速度 406 rad/s、トルク定数 `1.5·P·ψm` = 0.0195 N·m/A、いずれも小型モータとして整合。
2 点の逆算でオフセットが両点とも 0.262 V で一致し「一定オフセット」モデルの裏づけになった (デッドタイム損。6b の根拠)。

### FF を入れて見えた別問題: 角度が速度に比例して遅れていた

FF 自体は正しく効いていた (182 rad/s で FF 2.37 V、理論 2.362 V)。しかし PI が FF を打ち消す方向に強く効いていて (Vq 0.45 V に対し PI −1.92 V)、
推定角のずれの典型症状だった。`Vd` で比較すると決定的:

| 速度 | Vd 実測 | 角度が正しければ `−ω_e·L·Iq` |
|---|---|---|
| 20 rad/s | −0.03 V | −0.001 V |
| 120 rad/s | **−1.25 V** | −0.011 V |

`Vd = R·Id − ω_e·L·Iq − ω_e·ψm·sin δ`, `Vq = R·Iq + ω_e·L·Id + ω_e·ψm·cos δ` を解くと δ は 6.2° (20 rad/s)、49.4° (120 rad/s) で
速度に比例し、**一定の時間遅れ 約 1.08 ms**。内訳は演算遅れ 0.075 ms と**センサ側 (AS5600 の内部フィルタ) 約 1.0 ms**。
2 次 PLL (ζ=1) は等速回転で定常位相遅れが 0 なので犯人ではない。

### 角度遅れ補償 (6a)

推定角を `ω̂ × 遅れ` 進める。FF は角度が正しいときにしか効果を出さないので、これを直すまで 5 の利得は出なかった。

| | 補償前 (120 rad/s) | 補償後 (247 rad/s) |
|---|---|---|
| `Vd` | −1.25 V | 平均 **+0.01 V** (±0.3 のばらつき) |

電圧の収支も閉じた (247 rad/s で必要 Vq 3.28 V に対し実測 3.33 V。補償前は 2.1 V 合わなかった)。
補償前は `cos(49°) = 0.66` しかトルクにならず残りが d 軸に無駄流れしていたが、補償後は 0.3 A で 247 rad/s (補償前は 1.0 A で 182 rad/s)。
補償後に角度が正しい状態で ψm を直接計算すると 0.001884 Wb で、2 点法の 0.001854 と差 1.6%。再測は不要だった。

**遅れ時間 `ANGLE_DELAY_DEFAULT` (1.08 ms) はスイッチ校正で自動測定して Flash に保存される** (1 回の測定で `sin δ = (Vd − R·Id + ω_e·L·Iq)/(ω_e·ψm)` から求まる。
検算: 補償前 1.074 ms、補償後 1.077 ms)。

## プロファイラの使い方

`config.h` の `PROFILE_ISR` で有効化する。実体は [lib/profile/profile.h](../lib/profile/profile.h)。

```c
#define PROFILE_ISR 2              // 0:無効  1:全体のみ  2:内訳も
#define PROFILE_PRINT_INTERVAL_S 1.0f
```

DWT の `CYCCNT` を区間の前後で読んで引き算する (1 サイクル = 13.9 ns)。デバッガ不要。
GPIO トグル + オシロと違い、**最大値と平均を長時間積算でき**「たまに 1 回だけ長い」を捕まえられる。

### 出力例

```
BLDC: プロファイル有効 (PROFILE_ISR=2) 計測オーバーヘッド 11 cycle/区間 (0.153us)
[PROF] irq  X.XX/ X.XXus  CPU XX.X%  rate 20.00kHz  cb  X.XXus  周期 50.00-50.00us
       内訳: PLL X.XXus  電流ループ X.XX/X.XXus  外側 X.XXus (1.00kHz)
```

| 項目 | 意味 |
|---|---|
| `irq` 平均/最大 | 割り込みハンドラ全体 (HAL のディスパッチ込み)。最大が `ISR_DEADLINE_US` を超えると警告が出る |
| `CPU` | 合計サイクル数 ÷ **実経過時間** |
| `rate` | 実測した割り込み頻度 |
| `cb` | `HAL_ADC_ConvCpltCallback` の中身だけ。`irq − cb` が HAL のオーバーヘッド |
| `周期` min-max | 50 µs から外れていたら ADC トリガか割り込み優先度を疑う |

判断の目安:

- **`rate` が 20.00 kHz でない** → 想定外の割り込み源がある。他の数字が意味を失う (DMA ハーフ転送割り込みはこれで見つけた)
- **`irq` の最大が 50 µs に近い** → 処理を足す余裕は無い。まず減らす
- **`irq − cb` が大きい** (数 µs) → `DMA1_Channel1_IRQHandler` をベアメタル実装にする価値がある
- **`周期` の max が 50 µs を大きく超える** → 1 回取りこぼしている。致命的
- **どこかが不自然に重い** → `objdump -d` して `vcmpe.f32` / `vmrs` の数を見る

### 注意

- 計測自身のコストは起動時に実測して表示される
- `PROFILE_ISR = 2` は計測点が 5 箇所になり `irq` が 0.5〜1 µs 水増しされる。**内訳を見るなら 2、CPU 使用率の正確な値なら 1**
- 表示は `printf` (USART1, 250000 baud, ブロッキング) なのでメインループだけが待つ。制御ループは割り込み優先度 0 なので影響を受けない
- 測り終わったら `PROFILE_ISR = 0` に戻す (計測コードごと消える)
