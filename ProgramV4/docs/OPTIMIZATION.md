# ProgramV4 最適化メモ

性能に関わる設計の理由・結論の数値・残課題。パラメータの意味と根拠は `src/app/config.h`、
制御の構成と校正の手順は [FOC.md](FOC.md)。

## 大前提: 制御周期も PWM 周波数も上げない (20 kHz)

- 最高速度 `MAX_ANGULAR_SPEED = 150 rad/s` × `POLE_PAIRS = 7` = 電気角 167 Hz。20 kHz なら電気1周期に 120 サンプルで、FOC の定石 (10〜20) の10倍近い
- トルク・制動・停止モードは車輪として外から回され、`OVERSPEED_DIRECT_IQ_RAD_S = 270 rad/s` まで回りうる。このときでも電気1周期 66 サンプル
- 電流リプル `ΔI_pp ≈ Vdc / (4·L·fsw)` は約 0.3 A_pp で `MAX_CURRENT = 10 A` の 3%

電流ループは PWM と 1:1 (デューティは1周期に1回しか更新できない)。PWM 周波数を上げると
(1) スイッチング損失が比例して増え、(2) ローサイドシャントのサンプリング窓が絶対時間で縮んで `MAX_DUTY` を下げるしかなくなり最高速度が落ちる。→ **20 kHz が最適点。**

## 現在の実行時間 (2026-10-19 実測、速度制御 30/120 rad/s、`PROFILE_ISR=2`)

```
[PROF] irq 22.14/27.83us  CPU 44.3%  rate 20.00kHz  cb 20.10us  周期 49.85-50.14us
       PWM書込 20.00/20.36us (期限 23.4us)
       内訳: PLL 7.53us  電流ループ 11.11/11.25us  外側 5.25us (1.00kHz)
```

- 期限 `ISR_DEADLINE_US` (23.4 µs) と比べるのは割り込み全体ではなく「入口から CCR 書き込みまで」(`PWM書込`)。余裕は約 3 µs
- 外側ループ (1 kHz) はデューティ書き込みの**後**に回す。Iq 指令の反映は 50 µs 遅れるが外側ループの周期 1 ms に比べて無視できる
- 外側ループの tanh は libm の `tanhf` (1回約 6.5 µs) ではなくパデ近似 `BLDC_TanhApprox`。`tanhf` のままだと 1 ms ごとに期限を超えた
- エンコーダ処理 (表示名 PLL) が重いのは ADC 14回平均・補正テーブル・飽和直後の棄却のため。割り込みに処理を足すなら先にここを軽くする (2d)

## 残課題

### 6b デッドタイム補償

DTG = 20 → 278 ns (周期の 0.56%)。ψm 同定で Vq に約 0.26 V の一定オフセット (校正 6 の V0) が出ており、
電流の向きで符号が反転するので Iq がゼロを跨ぐたびに約 0.52 V 飛ぶ。低速トルクリプルの原因。

### 6c その他の制御の改善

- **位置制御の D 項**: 誤差の微分 + LPF をやめ、PLL の ω̂ を使う (`d_term = -kd * angular_speed`)
- **1.5 周期の演算遅れ補償**: 逆 Park 用の角度だけ `+ ω_e × 1.5 × CURRENT_LOOP_DT` 進める。電流帯域の上限が少し上がる
- **低速のトルク脈動**: 10 rad/s で 1周14回 (電気角2倍) の速度の揺れ約 2 rad/s が残る。補正テーブルの有無で変わらないので
  センサではなく実トルクの脈動 (コギング等)。コギング補償は一度入れて外した (中速に効かず高速で悪化。Flash BLD6→BLD7)
- **相抵抗の偏り**: 校正 1 の角度ごとの R から、U相 (OUTC) の経路に約 0.04 Ω の余分な抵抗の疑い (FOC.md「校正とモータ定数」)

### アンプ整定時間を ADC で測る (`MAX_DUTY` の引き上げ)

`CURRENT_SENSE_SETTLING_COUNTS = 144` (2.0 µs) は INA181A1 の帯域 350 kHz (τ = 455 ns、1% 整定 = 4.6τ = 2.1 µs) からの
**保守的な見積もりで、実測していない**。実測すれば `MAX_DUTY` 0.92 (変調率 0.485) まで見込める。オシロ無しで ADC 自体で測れる (未実施):

1. 開ループでロータを固定し、一定の直流電流を流す
2. `TIM1->CCR4` を低側 ON 直後から頂点までスイープ
3. 各点で電流を平均して記録
4. 低側 ON 区間内の真の電流は一定なので、読み値が平らになった点が整定完了

デューティ 0.65 / 0.425 / 0.425 で駆動すれば U 相と V 相で低側 ON の時刻が違い、1 回のスイープで独立した 2 測定が取れる。

### エンコーダの根本対策 (次の基板)

CurcuitV4 は AS5600 の SDA/SCL が未接続でアナログ出力しか使えない。I²C で読めば飽和・盲点・遷移グリッチがまとめて消える (V5 基板の課題)。
オブザーバでは AS5600 のフィルタ遅れ (約 1 ms) より速い情報は取り戻せず、できるのは遅れの補償 (6a) だけ
(Iq からの加速度予測を入れた3次オブザーバは、2次 PLL の加速度誤差 a/PLL_KI が無視できるので採用しなかった)。

## 設計の理由 (完了項目)

### 2b/2c: ISR の削減

- ADC1 の DMA は 2 変換なので、1 変換目でハーフ転送割り込みが立ち割り込みが 40 kHz になっていた。
  `current_sense.c` で `__HAL_DMA_DISABLE_IT(hadc1.DMA_Handle, DMA_IT_HT)` として止めている
- CPU 使用率は「合計サイクル数 ÷ 実経過時間」で出す (想定周波数を掛ける計算は実レートが違うと静かに外れる)
- Cortex-M4F の float 比較は `VCMP.F32` + `VMRS` で分岐込み 1 回 8〜10 サイクル。対策として:
  1. `mymath.h` の `Abs()` は `_Generic` で float を `__builtin_fabsf` (`VABS.F32`) に振り分け
  2. `FOC_SinCos` は内部で小数部を取るので入力範囲は任意。事前に正規化しない。sin/cos を1回の縮約で取る (誤差 1.9e-5)
  3. デューティのクランプは整数比較 (`BLDC_DutyToCcr`)。`VCVT` が NaN を 0、範囲外を飽和させるので入力が何でも範囲に収まる

### 2d (見送り): CCM RAM 実行のメモ

- HAL のディスパッチ (`irq − cb`) は約 1.5 µs。DMA 割り込みフラグを直接クリアするベアメタルのハンドラにすれば消せる
- 72 MHz は `FLASH_LATENCY_2`。CCM SRAM (4 KB) は命令フェッチでき 0 ウェイト
- やるなら (1) `startup_stm32f303x8.s` に `.ccmram` をコピーするループを追加 (リンカスクリプト [STM32F303XX_FLASH.ld](../STM32F303XX_FLASH.ld) の `.ccmram` 定義は用意済み)、
  (2) ホットパスの関数に `__attribute__((section(".ccmram")))`。ホットパスは約 3.2 KB (計測時) で 4 KB に対し余裕が少なく、ベアメタル化とセットになる

### 3: センター揃え PWM

| | 値 |
|---|---|
| カウントモード | センター揃え (`CENTERALIGNED1`)、`PWM_ARR = 1800` (`72M/(2×ARR)` = 20 kHz) |
| デューティ | `CCR/ARR` |
| ADC トリガ | `CCR4 = ARR − CURRENT_SENSE_TRIG_ADVANCE = 1750` (低側 ON 区間の中央) |
| `MAX_DUTY` | 0.88 (`MAX_DUTY_CCR = 1584`)、変調率 0.439 |

- 低側 ON 区間は頂点を中心に両側へ広がるので、エッジ揃え (区間の片側しか使えず `MAX_DUTY` 0.80) より上限を引ける
- 頂点でサンプリングするので、取れる値が三角波リプルの平均 = その周期の平均電流。`CURRENT_LPF_COEF` を 0.5 まで緩められる
- タイマ設定は `tim.c` (CubeMX の再生成で消える) ではなく `BLDC_InitPwmTimer` で上書きする
- 整合は `config.h` の `_Static_assert` で検査する (`MAX_DUTY_CCR` / `CURRENT_SENSE_TRIG_ADVANCE` / `CURRENT_SENSE_ACQ_COUNTS` / `PWM_ARR`)。`_Static_assert` は整数しか扱えないので `MAX_DUTY` は整数の `MAX_DUTY_CCR` を正とする

### 4: 電流ループの帯域

- PI は `Kp = L·ω_bw`, `Ki = R·ω_bw` で、ゼロ点 Ki/Kp をプラントの極 R/L に合わせる (極零相殺)。
  固定ゲインの時代は Ki/Kp = 1000 に対し実際の R/L ≈ 5000 で、応答が速い成分と 1.3 ms の尾に割れていた
- 帯域の上限は位相遅れで決まる (700 Hz で 1.5 周期の演算遅れ 18.9° + 電流 LPF 17.6° → 位相余裕 約 53°)。狙いは `CURRENT_BW_TARGET_HZ = 700`
- `ω_bw = Kp/L` は遅れ 0 を前提にするので実測は 2〜3 割低く出る。校正 2 が実測して設計帯域 (`current_bw_hz`) を割り戻す。
  「設計値」と「達成したい帯域」を分けておかないと、実測を設計値に合わせる追いかけっこになる
- 測定は d 軸ステップ (トルクが出ずロータが動かない。SPM なので Ld = Lq)。63% 到達時間は線形補間し、半周期 (25 µs) の遅れを引く
- R は電圧の多点で最小二乗し、デッドタイムの一定電圧損 (V0) を切片として分離する。1点法だと R を約 9% 過大に読む
- 結果 (旧手順, 2026-07-29): R 0.1928 Ω、L 38 µH、95% 整定 0.50 ms、実測帯域 714 Hz、オーバーシュート 1.7%

### 5/6a: フィードフォワードと角度遅れ

- `Vd −= ω_e·L·Iq`, `Vq += ω_e·L·Id + ω_e·ψm`。モデル上、Iq 2 A ステップの 95% 到達は 160 rad/s で FF なし 1.55 ms → あり 0.55 ms (速度に依存しない)。
  符号を間違えると打ち消すはずの項が二重に効いて破綻する
- FF 単独で変調限界を超えると PI が制御権限を失うので `CURRENT_FF_MAX_RATIO` (0.85) で頭打ち
- 推定角は実位置より約 1.08 ms 遅れる (AS5600 内部フィルタ約 1.0 ms + 演算遅れ 0.075 ms)。2次 PLL は等速で定常位相遅れ 0 なので PLL のせいではない。
  補償前は 120 rad/s で δ = 49°、Vd が −1.25 V (正しければ −0.011 V)。補償後は 247 rad/s で Vd 平均 +0.01 V、電圧の収支も閉じた
- 遅れ時間は校正 6 が `sin δ` から自動測定する (初期値 `ANGLE_DELAY_DEFAULT`)
- 結果 (旧手順, 2026-07-29): ψm 0.001854 Wb (1点法なら +25%)、Kt = 1.5·P·ψm ≈ 0.0195 N·m/A、無負荷到達速度 約 406 rad/s

### 7: エンコーダの継ぎ目と補正テーブル

補正テーブルを強制転流のビン平均で作ると「センサの誤差」と「ロータが強制角からずれた量」(コギング、電流センサのゲイン差など) を区別できず、
テーブルに 1周14回 (電気角2倍) の偽の誤差が入って速度ループがそれを追い、トルク脈動になった。
→ 出力を切った惰性回転で作る方式にした (校正 5、Flash `BLD8`)。2026-10-19 の実機結果 (校正: 残差 RMS 0.0014 rad、補正最大 0.0228 rad):

| 速度 [rad/s] | テーブル | ω̂ σ | 14回/周 | 1回/周 | emax [rad] |
|---|---|---|---|---|---|
| 10 | あり / なし | 1.33 / 1.41 | 1.97 / 2.1 | 0.07 / 0.12 | 0.024 / 0.031 |
| 30 | あり / なし | 0.41 / 0.76 | 0.84 / 1.17 | 0.03 / 0.43 | 0.013 / 0.031 |
| 120 | あり / なし | 0.83 / 1.41 | 0.65 / 0.36 | 0.30 / 1.94 | 0.012 / 0.039 |

全速度でテーブルありがなしより良い。比較は自己試験 (`SELF_TEST_RUN`、`BLDC_SetEncoderLutEnabled`) と状態表示の速度の揺れ診断で行う。

AS5600 の磁石とロータの位置関係がずれるとオフセットが狂いトルクが逆向きに出て暴走する (実機で電気角約 195° ずれた例あり)。
過速度保護 (`OVERSPEED_LIMIT_RATIO` / `OVERSPEED_DIRECT_IQ_RAD_S`) はその対策。磁石の固定を確認すること。

## プロファイラの使い方

`config.h` の `PROFILE_ISR` と `PROFILE_PRINT_INTERVAL_S` で有効化する。実体は [lib/profile/profile.h](../lib/profile/profile.h)。
DWT の `CYCCNT` を区間の前後で読んで引き算する (1 サイクル = 13.9 ns)。最大値と平均を長時間積算でき「たまに1回だけ長い」を捕まえられる。

| 項目 | 意味 |
|---|---|
| `irq` 平均/最大 | 割り込みハンドラ全体 (HAL のディスパッチ込み) |
| `CPU` | 合計サイクル数 ÷ 実経過時間 |
| `rate` | 実測した割り込み頻度。20.00 kHz でなければ想定外の割り込み源がある |
| `cb` | `HAL_ADC_ConvCpltCallback` の中身。`irq − cb` が HAL のオーバーヘッド |
| `周期` min-max | 50 µs から外れたら ADC トリガか割り込み優先度を疑う。max が大きく超えたら取りこぼし |
| `PWM書込` | 入口から CCR 書き込みまで。最大が `ISR_DEADLINE_US` を超えると警告 |
| `内訳` (`PROFILE_ISR=2`) | PLL (エンコーダ処理) / 電流ループ / 外側ループ |

- `PROFILE_ISR = 2` は計測点が増えて `irq` が 0.5〜1 µs 水増しされる。内訳を見るなら 2、CPU 使用率の正確な値なら 1
- 表示は `printf` (USART1, 250000 baud, ブロッキング) でメインループだけが待つ。制御ループは優先度 0 なので影響しない
- 不自然に重い箇所は `objdump -d` で `vcmpe.f32` / `vmrs` の数を見る
- 測り終わったら `PROFILE_ISR = 0` に戻す (計測コードごと消える)
